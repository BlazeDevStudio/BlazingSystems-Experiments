# PAY-0716 — OFF-DEVICE controller sequence/pending reservation fixture

This **test-only** .NET8 program is **not part of the installed BlazePisonet SoftTimer app or EXE**. It is not a production controller, a signed customer ACK verifier, or a v1 money migration. P0 #31, #32, #34, #43 remain OPEN; `VERSION=0.5.3` and customer v0.6 installation are blocked.

A private disposable `blaze-v2-pending-XXXXXXXX` directory directly under the platform temporary directory must already contain `.blaze-v2-pending-synthetic-only` with the exact marker `BLAZE-V2-PENDING-SYNTHETIC-ONLY\n`. The fixture refuses missing state (never resets sequence to zero), arbitrary paths, marker removal, corrupt canonical state and noncanonical fields. On Unix the marker and directory must not be group/world-accessible.

The state file includes a version, controller ID, monotonic high-water sequence and at most **one immutable pending payment**. A new reservation writes and flushes the entire new state to a same-directory temporary file and renames it; a simulated pre-rename failure makes no reservation, while simulated post-rename lost response must be resolved by reading the pending event. A restart may retransmit the *exact* original command; a different amount, destination, timestamp or opcode is rejected until the pending receipt is explicitly cleared. An orphaned staging file blocks further work.

The CLI supports fixture-only `--init ROOT CONTROLLER`, `--reserve ROOT OP SUBJECT TARGET UNITS TIMESTAMP`, `--pending ROOT`, and `--ack ROOT SEQ OP SUBJECT TARGET UNITS TIMESTAMP NATIVE_FIXTURE_RESPONSE`. The ACK parser only recognizes `COMMIT<TAB>integer` or `REPLAY<TAB>integer` and checks the entire pending request, but the text response is **not authenticated**: it must never be treated as a customer-paid ACK or enable an installed sender. The signing envelope and native HMAC journal are exercised by `experiment/openwrt/BlazePwifi/tests/v060_softtimer_pending_v2_restart.sh`; the Windows process fixture is `windows-selftest.ps1`.

**Durability boundaries:** `FileStream.Flush(true)` and same-directory `File.Move(..., overwrite:true)` exercise staged write plus process restart, but there is **no proven durable parent-directory fsync or real Windows sudden-powercut test**. SHA-256 detects corrupted content, **not** a previously valid, rolled-back state (requires #43 trusted independent witness). File locking is exercised but not proven across multiple real controllers/partitions. A production implementation needs authenticated provisioned ACKs, signed v2 sender protocol, secure key handling, power-loss-tested durable sequence+pending, migration controls and positive monotonic witness acceptance; none is supplied here.

Never pass real device keys or customer records to this fixture, publish it with the Windows portable installer, or copy it into OpenWrt rootfs.
