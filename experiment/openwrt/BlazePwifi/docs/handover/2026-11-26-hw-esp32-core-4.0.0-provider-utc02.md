## Scope

No firmware .ino, controller response schema, coin/relay policy, finance, replay, signer, witness, updater, or COE destination source changed in this activation.

The existing #340 ESP32 sketch already contains the version-gated provider implementation:

- Mbed TLS 4: psa/crypto.h, psa_crypto_init() and psa_hash_compute(PSA_ALG_SHA_256, ...).
- Mbed TLS 3: mbedtls/sha256.h and the legacy init/start/update/finish/free sequence.
- Both paths reject provider failure and wrong digest length.
- signedBody() rejects malformed/empty SHA-256 hex before recording the nonce.
- post() rejects empty signed bodies before opening the HTTP request and denies non-register/poll actions.

This activation added one Hardware-owned workflow:

.github/workflows/phx-hw-esp32-core-4.0.0-compile.yml

It pins Arduino ESP32 core 4.0.0, checks out the exact event SHA, runs the existing provider/failure-injection source lab, compiles the actual Vendo sketch, and verifies/hashes the application .ino.bin rather than a partitions/bootloader image. The workflow is push-only for this Hardware branch (plus manual dispatch) to avoid duplicate push/PR builds.
