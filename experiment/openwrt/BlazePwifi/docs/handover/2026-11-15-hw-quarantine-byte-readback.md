## 2026-11-15 — PHX-HARDWARE: non-destructive coin journal mount, fail-closed admission

- **Source commit:** [`354a303373b1e108f0f62219a3bbcba8b335e6da`](https://github.com/BlazeDevStudio/BlazingSystems-Experiments/commit/354a303373b1e108f0f62219a3bbcba8b335e6da) under DRAFT PR #293, stacked on #283. This work modifies ONLY PHX-HARDWARE's ESP8266/ESP32 sketches, their scoped test/maintainer documents, and the preexisting narrowly scoped focused workflow (PHX-RELEASE review requested). No CORE backend, financial schema, lease authority, customer binaries or hardware device touched.
- **Verified defect:** ESP8266 `initPendingStore()` previously formatted the LittleFS volume on `begin()` failure, and ESP32 `setup()` called `LittleFS.begin(true)` with format-on-fail enabled. A failed/corrupt mount can still contain old unpaid coin and quarantine records, so formatting destroys potential reconciliation evidence. This is a startup-data-integrity problem even when the app's relay is off.
- **Patch:** Both controllers now expose `initPendingStore()`; ESP8266 `LittleFS.begin()` and ESP32 `LittleFS.begin(false)` mount non-destructively. On failure, preserve the filesystem bytes, leave `fsReady=false`, skip `loadPending()`, log recovery requirement; `applyOutputs()` keeps LED/coin relay denied. Successful mount loads the existing journal through its original parser; no financial API or relay policy silently changed.
- **Source-linked new regression:** `esp32/BlazePwifiVendo32/journal_mount_failclosed_lab.py` extracts actual C++ `initPendingStore()` and `applyOutputs()` per board and compiles against fake LittleFS. Six scenarios each board check mount denied, successful load/outputs, pending event, coin disabled, controller disabled, no insert, no auto-format and exact load invocation. It does not test physically mounted flash, actual coin hardware or persistent post-power loss.
- **Actual CI:** Focused exact-source [run #43643397940](https://github.com/BlazeDevStudio/BlazingSystems-Experiments/actions/runs/43643397940), job 132595675413 **COMPLETED SUCCESS**: ESP8266+ESP32 quarantine 22/22 + no-format mount/output 12/12 = **34/34 simulated host assertions PASS**.
